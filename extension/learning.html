Understand what you’re building.

These are general lessons, not a description of your assistant’s private reasoning or your project. Interlude will bring you back when a watched task needs you.

How a frontend talks to a backend

The browser sends an HTTP request to an API. The server validates it, performs authorized work, and returns a response. The frontend renders the result and handles loading and error states.

Where should access control live?

On the server for every protected operation. Hiding a button in the frontend does not prevent someone from sending the request directly.

What makes a test useful?

A test checks an observable promise: given a particular input or user action, does the system produce the right result? Include failures and boundary cases, not only the happy path.

What should you review when the task finishes?

Check the changed behavior, the evidence from tests, and what remains unverified. Run the user flow yourself when it depends on a browser, permissions, or another service.
